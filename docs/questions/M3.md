# M3 interpretations

#29 · Single public function api/requests.ts (router, key "" = POST /api/requests); feed GET and listener search (#31) join the same router; vercel.json rewrites /api/requests/:path* to it
#29 · Listener cookie `ttunes_listener`: HS256 JWT signed with SESSION_SECRET, audience "ttunes-listener", 1 year; the owner session has no audience and needs the owner sub, so neither passes as the other
#29 · IP hash = HMAC-SHA256 of the client IP (x-forwarded-for first entry, else socket) keyed by IP_HASH_SALT if set, else derived from SESSION_SECRET (rotating the secret orphans old hashes, only loosening the backstop)
#29 · "One active request" counts waiting and queued only; a playing request frees the listener. Hourly count includes denied and expired ones
#29 · "Already coming up" = playing now, in the owner queue, or another request waiting/queued/playing for the same video; a song only in the shuffle is NOT refused
#29 · Waiting duplicates of the same video from different listeners are refused too (one waiting copy is enough for the owner to judge)
#29 · Rules run before YouTube (refusals cost no quota) and again under the station lock; refusal order: off, active request, already coming up, then 5/hour and the daily cap (the attempt is recorded here), then YouTube (embeddable/missing), then over 15 min; the state rules run again under the lock after the lookup
#29 · Over 15 minutes refused (422 too_long); Music under 10 minutes (strictly) auto-queues in open mode; exactly 10 minutes waits
#29 · A waiting request older than 24h stops blocking at once (checks ignore it) and is marked expired lazily on the next post, and by the daily cron
#29 · Requests keep their own title and length and never join the library; played requests stay in the requests table (feed reads them there)
#29 · Requests queue in order of when they became queued (an approval puts it at the back); the shuffle cycle is untouched while requests play
#29 · IP hashes older than 7 days are set to null by the daily cron (rows stay for the feed); the cron reply gains a `requests` field
#29 · Name/dedication are trimmed, counted in characters (code points), and reject control characters/newlines; HTML is stored verbatim and left to React to escape. Non-JSON body is a 400 (name missing)
#29 · Body field is `link` (any YouTube link or bare id); unknown fields are ignored
#29 · Added lib setMode(mode) and moderate(id, approve|deny|remove) for #32; they take the station lock and write activity_log (request_mode, request_approve/deny/remove); no endpoints
#29 · Fixed M2 leftover: a stale skip (409) on a station that never started no longer returns or starts `playing`
#29 · Every post that reaches YouTube is recorded in request_attempts (migration 008) before the call; the 5/hour limit counts attempts (accepted or refused) per cookie or IP, checked first
#29 · Global cap: 2000 listener lookups per rolling 24h (DAILY_LOOKUP_CAP in lib/requests.ts), then 503 code "paused" ("Requests are paused for today"); refusals before YouTube (off, active request, already coming up) cost no attempt
#29 · Attempts older than 7 days are deleted by the daily cron together with the IP-hash purge, which now takes the station lock first
#29 · YouTube quota/outage errors use code "youtube_unavailable"; a missing/blocked/live video stays "video_unavailable"
#29 · Text rejects only the spoofing set (bidi overrides/isolates U+202A-202E and U+2066-2069, U+200B, U+2060, U+FEFF, U+2028/2029, C0/C1 controls); ZWJ/ZWNJ and tag characters are allowed (Persian names, family/rainbow/England-flag emoji). A name needs a visible character: blank-looking ones (U+3164, U+2800, U+115F, U+1160, U+FFA0), format characters and combining marks alone do not count. More than 2 combining marks in a row is refused (no Zalgo)
#29 · IPv6 is hashed by its /64 prefix (IPv4-mapped addresses as IPv4); one home network shares one limit
#29 · lib/auth.ts exports sessionSecret() and sessionKey(); listener.ts uses them instead of its own copy
#30 · Public feed GET /api/requests/feed: newest 30, denied requests hidden (an abusive rejected message does not stay on a public page), a waiting request past 24h shows as expired even before the daily cron marks it; read-only, cached 10s
#30 · GET /api/requests/mine is separate and no-store: the caller's own waiting/queued/playing request (matched by cookie or network like the posting limit), or null; it never issues a cookie
#30 · Feed and own-request reload whenever useStation hands over a new `playing` object (join, song change, the 30s re-check) and right after a post; no timers of its own
#30 · Request box is hidden only when the feed says mode is off; if the feed fails to load the box stays (the server still refuses) and the feed shows an error with Try again
#30 · Picking a search result posts its bare videoId as `link`; the server re-fetches the metadata
#30 · After a post (success or refusal) the box re-reads `mine`; while a request is waiting/queued/playing the form is replaced by a notice, since only one is allowed
#30 · Labels differ from the owner panel ("Song link", "Search by name", "Find") so the existing owner e2e selectors stay unambiguous
#30 · e2e gives the second listener its own x-forwarded-for: `mine` matches by network too, so two browsers on one machine would otherwise share a request slot
#30 · `mine` matches by cookie only (a second cookie on the same network sees null); the network backstop stays for limits only. A post blocked only by another cookie's request on the same network gets code `network_busy` ("Someone on your network already has a request waiting or lined up. Try again once it plays."); your own cookie keeps `active_request`; the 5/hour message says "from your network" when only the IP hit the limit (code unchanged)
#30 · Combining marks are capped at 4 per grapheme (was 2 in a row), counted after stripping format and unassigned characters (ZWJ, ZWNJ, U+2061, tag chars, U+180E) so invisibles cannot split a Zalgo stack; Burmese, pointed Hebrew, Tibetan, Vietnamese NFD, Devanagari, Thai and keycap emoji pass
#30 · Feed cache header is `public, max-age=0, s-maxage=10, stale-while-revalidate=5` (browsers always revalidate, the CDN holds 10s)
#30 · Remove works on any request that isn't denied, including playing, played and expired ones, so you can take down any text. It's built in the moderation task (#32).
